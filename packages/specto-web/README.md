# specto-web

Static assets for Specto's web views, served to QtWebEngine over the `specto://` scheme
(`specto_app.web`). Nothing loads from the network at runtime, except the map's basemap
tiles under the `net:tiles` capability (docs/contracts.md 17).

```
web/
  bridge.js        JS side of the QWebChannel contract (window.Specto: connect, on, call,
                   emit, setParams, send, setHealth, report)
  monaco-env.js    Monaco loader + worker shim for a specto:// origin, "specto-calm" theme
  style.css        B Calm Canvas page chrome; token names match specto_app.theme
  json/            read-only JSON inspector (the selected item of its collection)
  markdown/        rendered note: markdown-it + github-markdown-css, Mermaid, KaTeX,
                   Obsidian callouts and [[wikilinks]] (render.js), outline, back history
  map/             MapLibre GL: one layer per GeoJSON file of its features input, layer
                   list (toggle, colour, fit), hover properties, click selects (emitted),
                   a raster basemap (none, OSM or Esri satellite imagery, web/basemaps.py);
                   frames the data on every reload; over a batch (200) the footer's meter
                   shows loaded / total with Load more (#181)
  vendor/          git-ignored; filled by build.py (vs/ = Monaco, markdown-it/, mermaid/,
                   katex/, maplibre-gl/, github-markdown-css/, one <name>.version each)
types/
  specto-api.d.ts  GENERATED by gen_types.py from api-info.json: SpectoApi.CommandMap,
                   ChannelValues, ViewStates, ThemeTokens, DataKind, ViewType ...
  specto.d.ts      hand-written: window.Specto, SpectoConfig, the notification payloads
```

## Build (once per checkout, needs Node >= 20)

```
uv run python packages/specto-web/build.py          # npm install + copy into web/vendor
uv run python packages/specto-web/build.py --check  # exit 1 when a pinned version is missing
```

`package.json` pins every library (`build.py` `VENDORS` maps package -> files to copy);
`web/vendor/<name>.version` records what was copied. The app locates the assets through
the tiny `specto_web` package: `packages/specto-web/web` in a source checkout,
`specto_web/web` inside a wheel, `SPECTO_WEB_ROOT` to override.
`specto_app.web.assets.require_monaco()` fails with the build command as its fix-it when
Monaco is not there.

## Types

```
uv run python tools/gen_api.py            # SDK + types/specto-api.d.ts
uv run python tools/gen_api.py --check    # both up to date?
cd packages/specto-web && npm run typecheck   # tsc over the // @ts-check pages
```

Pages are plain scripts (no bundler): `// @ts-check` plus
`/// <reference path="../../types/specto.d.ts" />` gives them `Specto.call("describe",
{...})` with the command's argument and result types, typed port values and
notification payloads.

## Page contract (short)

- `Specto.connect()` once; `Specto.on("config", cfg)` brings label, params, the links
  feeding the view (`inputs`), capabilities and the theme tokens (applied as CSS
  variables).
- Input port values arrive as `on("port:<name>", value)` (latest value; `null` when the
  link feeding the port went away) unless the host translates them into its own
  notifications (`item`, `notes`, `layers`); emit on an output port with
  `emit(port, value)` (capability `emit:<port>`).
- `setParams({key: value})` writes the view's own params as one user submit (capability
  `params:<key>`); the document echoes them back through `on("params", p)`.
- `call(name, args)` runs a command within the view's grants; `send(kind, payload)` is a
  page event for the host (a wikilink followed).
- `report({...})` tells `snap` what the page shows (rects in CSS px) so agents and
  scripted human tests can act on it.
